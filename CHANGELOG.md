# Changelog

All notable changes to this project are documented here.
This project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.0.0] - 2026-11-22

First release.

### Added

**Checks** — eleven, each producing a verdict with evidence, severity, remediation and
RFC references:

- `discovery` — TLS on every endpoint, discovery document reachable, `issuer` matches its
  own URL, advertised capabilities (RFC 8414)
- `redirect` — strict `redirect_uri` validation via 17 mutations of the registered URI,
  probing open redirection (RFC 6749 §3.1.2.3, RFC 9700 §2.1.3)
- `pkce` — PKCE enforcement for public clients; absent, `plain`, undersized,
  non-base64url and unknown-method challenges (RFC 7636, RFC 9700 §2.1.2)
- `response-types` — which `response_type` values the server answers, including implicit
  and hybrid flows (RFC 9700 §2.1.1)
- `token-auth` — token endpoint client authentication and error hygiene
- `state` — `state` echoed verbatim on success and error responses; missing-state and
  reused-state behaviour recorded as observations (RFC 6749 §4.1.2, §10.12)
- `refresh-reuse` — opt-in; replays a used refresh token to test rotation and reuse
  detection (RFC 9700 §2.2.2)
- `introspection` — opt-in; records what the introspection endpoint reveals, and whether
  it requires client authentication (RFC 7662)
- `jwks` — published JWK Set hygiene: private or symmetric keys, missing `kid`, weak RSA
  moduli (RFC 7517, RFC 7518 §3.3)
- `error-hygiene` — stack traces, SQL, filesystem paths and HTTP 5xx in error responses
- `token-leakage` — credentials appearing in redirect URLs, especially the query component

**Interfaces**

- Mode 1: all inputs as CLI flags
- Mode 2: `-i/--interactive` prompting, ending in a typed-hostname authorisation step
- `--dry-run` prints every request that would be sent, and sends nothing
- `--i-authorize-target` gate; without it the tool exits 3 and sends nothing
- Console output (TTY-aware colour, honours `NO_COLOR`), JSON and self-contained HTML
- `--checks` to run a subset, `--format` to choose outputs
- `--tui` — a terminal interface built from ANSI escapes and Unicode box drawing with no
  third-party dependency: ASCII-art banner, a target panel showing the resolved endpoints
  before any request is sent, a threaded spinner per check replaced by a one-line verdict
  with severity and elapsed time, a progress bar with a running request counter, a results
  dashboard (failures by severity, verdict counters, proportional status bar, overall
  verdict) and one bordered panel per finding. `-v` adds evidence. Width is read from the
  terminal and clamped to 40-120 columns
- `--tui` with no issuer/client/redirect-uri opens an interactive menu: guided audit, run
  with the current flags, dry run, self-test, or open a previously saved JSON report
- `--color {auto,always,never}`; `auto` keeps colour and cursor control off when stdout is
  not a TTY, so piped output stays greppable
- `--theme` / `NULLGRANT_THEME` — six colour palettes: `neon` (default, hot magenta on
  electric cyan), `matrix` (phosphor green), `toxic` (acid), `ember`, `ice` and `mono`.
  Colours are emitted as exact 24-bit RGB when the terminal advertises truecolor
  (`COLORTERM`), otherwise each snaps to a hand-picked 16-colour ANSI fallback; override
  with `NULLGRANT_TRUECOLOR=0|1`. Call sites use semantic roles (`brand`, `frame`, `fail`)
  rather than raw colour names, which is what makes a palette a one-line switch
- Non-UTF-8 terminals get an ASCII box-drawing fallback automatically
- Verdict colours are pinned identically across all six palettes — red is fail, amber is
  warn, green is pass, blue is indeterminate — and no chrome element shares the FAIL colour
  in 16-colour mode. A palette is cosmetic and can never change what a report means

**Distribution**

- `nullgrant.sh` — a shell launcher for people who would rather type `./nullgrant.sh` than
  `python3 nullgrant.py`. Resolves its own directory through symlinks, finds a `python3`
  (override with `PYTHON=`), verifies it is 3.8+, picks whichever layout is present, and
  `exec`s the tool so exit codes and signals pass through unchanged. `selftest` as the first
  argument runs the assertion suite. Four distinct failure modes (missing interpreter,
  non-interpreter file, Python too old, neither layout present) each give a one-line message
  and exit 1
- `tests/test_launcher.sh` — 31 cases covering both layouts, symlink invocation, running from
  `/`, argument passthrough, exit-code propagation, the TUI menu, `--color always` surviving
  the wrapper, and every failure mode

- `nullgrant.py` — a single-file edition with the whole package merged into one script, so
  it can be copied to a target box and run with a stock `python3`: no install, no unpack,
  no `PYTHONPATH`. Generated by `tools/build_singlefile.py`, which is AST-driven (modules
  topologically sorted, imports removed by exact line range, stdlib imports hoisted and
  de-duplicated) and deterministic, so CI can regenerate it and fail on any drift
- `tests/compare_singlefile.py` — proves the two forms are behaviourally identical: same
  exit codes and byte-identical JSON reports across three fixture scenarios, after
  canonicalising per-run random values, with a baseline assertion that the same form run
  twice matches itself
- `tests/selftest.py` is layout-agnostic: `submod()` resolves `nullgrant.tui` in the package
  and falls back to the merged namespace, so all 143 assertions pass against `nullgrant.py`
  alone

**Lab support**

- `--target-ip` connects to an address you choose while keeping the issuer hostname in the
  Host header and TLS SNI, verifying the certificate against that hostname
- `--ca-bundle` trusts a lab CA while leaving hostname verification enabled
- `--session-cookie` and `--auth-code` let checks get past the login page and exercise the
  token endpoint

**Safety**

- Credential-like values are truncated in all output (`<redacted len=43 ya29...>`)
- Attacker-controlled probe domains use the RFC 2606 reserved `.invalid` TLD
- Redirects are never followed, so `Location` headers can be inspected directly
- Every check treats an unreachable endpoint as INDETERMINATE, never as PASS
- Reports record platform, Python version, tool version and connection settings

**Testing**

- `tests/mock_as.py` — a deliberately misconfigured authorization server and a correctly
  configured one, both bound to 127.0.0.1, so the checks can be verified differentially
- `tests/selftest.py` — 143 assertions covering every build step, runnable with no
  third-party dependencies. The 22 `tui` assertions check that `--tui` cannot change a
  verdict (same exit code and same finding set as a plain run), that nothing but plain
  text escapes when stdout is piped, that no drawn line exceeds the terminal width, and
  that `tui.py` imports nothing outside the standard library. The 33 `theme` assertions
  check that all six palettes produce an identical verdict/severity/exit-code signature,
  that verdict colours are invariant across palettes in both colour tiers, and that no
  chrome element collides with the FAIL colour

### Fixed during development

- **The package could not be imported at all on Python 3.8 through 3.11.** `report.py`
  formatted a severity colour through a dict literal written across two lines inside a
  single-quoted f-string. PEP 701 lifted that restriction in 3.12; before it the tokenizer
  rejects the construct with `SyntaxError: EOL while scanning string literal`. Because
  `report` is imported by `cli`, the whole tool was unimportable on four of the six
  supported versions — and invisible locally, since the development interpreter is 3.13.
  `ast.parse(..., feature_version=(3, 8))` does *not* catch this either: `feature_version`
  covers only a handful of grammar changes, not f-string tokenization. The mapping is now a
  module constant, and the lint job runs
  `ruff check --select E9,F --target-version py38` over every source file including the
  generated `nullgrant.py`, so newer-than-3.8 syntax now fails fast on 3.13 instead of only
  on four matrix legs. Verified on real CPython 3.8.20, 3.9.25, 3.11.18 and 3.13.18.
- **`tests/compare_singlefile.py` was flaky in roughly 1 run out of 10**, which made the
  "single file is behaviourally identical to the package" CI gate unreliable. The
  canonicaliser suppressed per-run random values with `\b[A-Za-z0-9_\-]{24,}\b`, but `-`
  and `_` are inside that class while `\b` is defined over word characters only. Probe
  identifiers end in `secrets.token_urlsafe()` output, whose alphabet includes both, so a
  suffix ending in `-` matched one character short and left `'<RANDOM>-'` in one run against
  `'<RANDOM>'` in the next — two identical reports comparing unequal. The delimiters are now
  explicit non-token lookarounds, and a regression guard asserts that five suffix shapes
  (`K`, `-`, `_`, `a-`, `9_`) all canonicalise identically while a short token still does
  not match. Mismatches also print a structural diff by JSON path
  (`$.findings[9].evidence[0].probes[0].body_snippet`) instead of only naming the top-level
  key that differed; that is what localised this one.
- **21 dead-code findings** from running ruff's pyflakes rules for the first time across
  every source file: 16 unused imports and f-strings with no placeholders, and 5 locals
  assigned but never read — including `registered_origin` and `as_origin` in the redirect
  check. Those two were checked rather than deleted blindly: origin comparison is done once,
  centrally, in `AuditContext.probe_authorize`, which classifies every response as
  `redirect-to-client` / `redirect-to-as` / `redirect-off-site`. They were leftovers from
  before that refactor, not a missing comparison.
- **`tools/build_singlefile.py` used `sys.stdlib_module_names`, which is Python 3.10+.**
  The generator therefore crashed on the 3.8 and 3.9 legs of the matrix, where CI
  regenerates the single file and `cmp`s it against the committed copy. It now uses the
  same directory-scanning fallback as the self-test, and its output is verified
  byte-identical whether produced by 3.8 or 3.13.
- **`sys.stdlib_module_names` is Python 3.10+**, but the CI matrix runs 3.8 and 3.9. Both
  the workflow's "no third-party imports" gate and the self-test's stdlib assertion would
  have failed on those two versions. They now fall back to scanning the stdlib directory —
  including `lib-dynload/`, which is where C extensions such as `unicodedata` actually
  live; scanning only the root silently missed them.
- **The launcher reported an unusable interpreter as merely "too old".** When `$PYTHON`
  pointed at a nonexistent path or a non-Python file, the shell's own error text was spliced
  into the version message, producing `"...: No such file or directory is too old."`. The
  two failures are now checked separately, and `tests/test_launcher.sh` asserts the "too old"
  wording cannot appear for an interpreter that will not run at all.
- **The single-file merge dropped function-local imports.** The builder deleted every
  `import` node but only hoisted module-level ones, so `import subprocess` inside
  `tui._run_selftest()` vanished and left a `NameError` waiting at its call site. It stayed
  hidden because `textwrap` and `json` — also imported inside functions — happen to be
  imported at module level elsewhere. Found by the AST undefined-name scan, not by any test.
  The builder now hoists every stdlib import regardless of nesting, and fails loudly on an
  import it does not recognise.
- **`_run_selftest()` could not find `tests/` in the single-file layout.** It derived the
  repository root as `dirname(dirname(__file__))`, which is correct for
  `nullgrant/tui.py` but one level too high for `nullgrant.py`. It now tries both.
- **Two 16-colour palette collisions.** Nearest-RGB snapping mapped neon's hot-magenta
  `brand`/`bar` and ember's `accent` onto bright red — the same base colour as `fail`, so a
  progress bar could read as a failure. Every role now has a hand-picked fallback, and the
  self-test asserts the collision cannot recur.

These were found by the self-test or by differential fixture runs, before release:

- `--session-cookie` raised `AttributeError` — it poked at an internal attribute removed by
  the `--target-ip` refactor. Cookies are now a first-class `HttpClient` parameter.
- `--target-ip` silently ignored `--ca-bundle` and `--insecure-tls`, because the custom TLS
  handler did not forward its SSL context to `HTTPSConnection`.
- `error-hygiene` and `token-auth` reported **PASS** when the target was unreachable and
  every probe had failed at the transport layer.
- The PKCE "undersized challenge" probe was sending a well-formed S256 hash of a short
  verifier, so it never tested what it claimed to.
- PKCE reported INDETERMINATE against a server that had explicitly rejected all five
  malformed-challenge probes.
- The refresh_token grant was advertised for a public client and scored as FAIL, though
  rotation and reuse detection cannot be observed externally. Now a labelled advisory.
- `MockAS.flavour` was a class attribute, so starting the hardened fixture silently
  reconfigured the running vulnerable one and invalidated every differential test.
- Discovery failures were not recorded in the report, leaving `metadata_source: null` with
  no explanation.
